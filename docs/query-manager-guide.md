# Query Manager 사용 가이드

## 서비스 개요

**Query Manager**는 SQL 쿼리를 작성, 실행, 저장, 버전 관리할 수 있는 웹 기반 쿼리 관리 도구입니다.

- **URL**: `http://192.168.1.250:8040`
- **백엔드**: nginx 리버스 프록시 뒤에 동작
- **쿼리 실행기**: `queryexecutor:18000` (Trino 기반)
- **DB 카탈로그**: `iceberg`, `postgresql` 두 개의 카탈로그를 지원

---

## 페이지 구성

| 페이지 | 경로 | 설명 |
|--------|------|------|
| 쿼리빌더 | `/query-builder` | SQL 작성/실행/저장 메인 IDE |
| 쿼리 변경 이력 | `/query-history` | 쿼리별 변경 내역 타임라인 & Diff 뷰어 |
| 릴리스 버전관리 | `/release-version` | 버전별 쿼리 묶음 관리 |
| DDL 생성기 | `/ddl-generator` | 스키마 변경/새 테이블 생성 DDL 도구 |

## 1. 쿼리빌더 (`/query-builder`)

쿼리빌더는 Query Manager의 핵심 페이지로, SQL 쿼리를 작성하고 실행하며 저장할 수 있는 통합 IDE 환경을 제공합니다.

### 1.1 화면 구성

```
┌─────────────────────────────────────────────────────────────────────┐
│ [Header] Query Manager | 쿼리빌더 | 쿼리 변경 이력 | ...  | [APS ▼] │
├────────────┬─────────────────────────────────┬──────────────────────┤
│ 저장된 쿼리  │  Query 1  | 테스트1  | +        │  매개변수 > 메타데이터 >│
│            │  [실행] [실행계획] [포맷]         │                      │
│ ┌────────┐ │ ┌─────────────────────────────┐ │  쿼리 ID: ________   │
│ │ 1.0.0  │ │ │ SELECT *                    │ │  쿼리 이름: ________  │
│ │ TEST1  │ │ │ FROM catalog.schema.table    │ │  쿼리 타입: [Read ▼]  │
│ │        │ │ │ WHERE project_id = @proj_id  │ │  릴리스 버전: [▼]     │
│ └────────┘ │ └─────────────────────────────┘ │  배포 상태: [▼]       │
│            │                                 │                      │
├────────────┤                                 │  [저장]               │
│ 카탈로그     │                                 │                      │
│ ▼ iceberg  │─────────────────────────────────┤──────────────────────┤
│   ▶ dev    │  결과 | 실행계획 | 콘솔            │                      │
│   ▶ mzc_aps│  쿼리를 실행하면 결과가 여기에       │                      │
│ ▼ postgres │  표시됩니다                        │                      │
│   ▶ mzc_aps│                                 │                      │
│   ▶ mzc_com│                                 │                      │
├────────────┴─────────────────────────────────┴──────────────────────┤
│ [Footer] queryexecutor : 18000                                      │
└─────────────────────────────────────────────────────────────────────┘
```

- **좌측 상단**: 저장된 쿼리 트리 (릴리스 버전, 배포상태 필터링)
- **좌측 하단**: 카탈로그 (DB 구조 탐색기)
- **중앙**: SQL 에디터 (멀티탭 지원)
- **우측**: 매개변수 / 메타데이터 / 변경 이력 패널
- **하단**: 결과 / 실행계획 / 콘솔 탭

### 1.2 도메인 선택

우상단의 도메인 선택 콤보박스에서 작업할 도메인을 선택합니다. 도메인은 데이터 소스와 권한 범위를 결정하며, 선택된 도메인에 따라 프로젝트 목록이 필터링됩니다.

| 도메인 | 설명 |
|--------|------|
| **APS** | APS 시스템 도메인 |
| **DP** | DP 시스템 도메인 |
| **CUSTOM** | 프로젝트 단위 쿼리 관리 (프로젝트 선택 필요) |

### 1.3 저장된 쿼리 패널

사용자가 저장한 쿼리들을 트리 형식으로 표시합니다. 각 쿼리는 고유한 ID를 가지고 있으며, 이를 통해 **다른 서비스에서 해당 쿼리를 호출하고 데이터를 페칭**할 수 있습니다.

**주요 기능:**
- **쿼리 목록**: 좌측 트리에서 저장한 모든 쿼리들을 확인
- **쿼리 선택**: 클릭하면 상세 정보와 실행 옵션 표시
- **폴더 구조 지원**: 그룹화된 폴더 구조로 쿼리 관리
- **컨텍스트 메뉴**: 쿼리 우클릭으로 삭제 및 경로(폴더) 변경
- **필터링**: 릴리스 버전, 배포상태로 쿼리 목록 필터링
- **검색**: ID 또는 이름으로 쿼리 검색

### 1.4 카탈로그 패널

쿼리 작성 시 필요한 데이터베이스 구조 정보를 트리 형식으로 제공합니다.

**현재 사용 가능한 카탈로그:**

```
iceberg
├── dev
│   ├── out_peg_info
│   ├── out_peg_info2
│   └── sample_table2
└── mzc_aps
    ├── odv_* (원본 데이터 뷰 테이블들)
    ├── ope_* (운영 실행 테이블들)
    ├── out_* (출력/결과 테이블들)
    └── rpt_* (리포트 테이블들)

postgresql
├── mzc_aps
│   ├── at_*  (시스템 마스터 테이블들)
│   ├── cfg_* (설정 테이블들)
│   ├── cp_*  (프로젝트 테이블들)
│   ├── dp_*  (DP 관련 테이블들)
│   └── dba_* (DBA 관리 테이블들)
└── mzc_com
    └── moz_project (프로젝트 마스터)
```

**주요 기능:**
- **DB 카탈로그 및 스키마**: 트리 형태로 표시하여 쿼리 작성 시 참조
- **테이블 정보**: 각 스키마 아래 테이블들을 나열
- **테이블 구조 확인**: 클릭하면 컬럼 정보 및 데이터 타입 확인
- **테이블 검색**: 키워드로 테이블 필터링

### 1.5 SQL 에디터

SQL 쿼리를 작성하고 실행할 수 있는 에디터입니다.

**테이블 참조 형식:**
```sql
-- catalog.schema.table_name 3단 형식으로 작성
SELECT * FROM postgresql.mzc_com.moz_project a
WHERE a.project_id = @project_id
```

> **필수 조건**: 모든 쿼리에 `WHERE project_id = @project_id` 조건이 **반드시** 포함되어야 합니다. 이는 멀티테넌시 격리를 위한 필수 요건입니다.

**주요 기능:**
- **자동완성**: SQL 키워드, 테이블, 컬럼명 자동완성 (`Ctrl+Space`로 트리거)
- **구문 강조**: SQL 구문에 맞게 색상 강조
- **여러 탭 지원**: 여러 쿼리를 동시에 작성 및 관리
- **파라미터 사용**: `@파라미터명` 형식으로 동적 쿼리 실행
- **실행계획**: 쿼리 실행 전 예상 실행 계획 확인
- **포맷**: 쿼리를 정렬된 형식으로 자동 포맷팅

**단축키:**

| 단축키 | 기능 |
|--------|------|
| `Ctrl + Enter` | 쿼리 실행 |
| `Ctrl + Shift + E` | 실행계획 보기 |
| `Ctrl + Shift + F` | 쿼리 포맷 |
| `Ctrl + /` | 주석 토글 |
| `Ctrl + Space` | 자동완성 트리거 |

### 1.6 매개변수 패널

쿼리 매개변수를 관리하는 패널입니다. `@파라미터명` 형태로 정의한 매개변수를 이곳에서 설정하고, 쿼리 실행 시 동적으로 값이 입력됩니다.

**주요 기능:**
- **매개변수 추가 및 관리**: 이름, 데이터 타입, 기본값 지정
- **매개변수 추출 마법사**: "SQL에서 @매개변수 자동 감지" 버튼으로 SQL에서 `@파라미터명`을 자동 추출하여 추가
- **고정 매개변수**: `project_id`는 고정 매개변수로 삭제 불가 (프로젝트 선택 콤보박스로 값 설정)
- **수동 추가**: `+` 버튼을 눌러 매개변수를 직접 추가

**매개변수 데이터 타입:**
- `S` (String): 문자열 타입

**사용 예시:**
```sql
-- @start_date와 @end_date를 매개변수로 사용
SELECT * FROM postgresql.mzc_aps.cfg_demand a
WHERE a.project_id = @project_id
  AND a.create_date BETWEEN @start_date AND @end_date
```

### 1.7 메타데이터 패널

작성한 SQL 쿼리를 저장된 쿼리로 관리하기 위한 메타데이터를 설정하는 패널입니다.

| 필드 | 설명 | 비고 |
|------|------|------|
| **쿼리 ID** | 외부 서비스에서 쿼리를 호출할 때 사용하는 고유 ID | 저장 후 수정 불가 |
| **쿼리 이름** | 쿼리 목록에서 표시되는 이름 | |
| **쿼리 타입** | Read / Write 등 쿼리 유형 | |
| **쿼리 설명** | 쿼리의 목적, 사용 방법, 주의 사항 기록 | |
| **릴리스 버전** | 쿼리가 속한 릴리스 버전 | |
| **배포 상태** | 개발중 / 배포완료 등 | |
| **경로** | 쿼리가 저장될 폴더 경로 | 폴더 선택 버튼으로 설정 |

### 1.8 변경 이력 패널

쿼리의 모든 변경 내역을 시간순으로 확인할 수 있습니다.

**주요 기능:**
- **변경 이력 타임라인**: 생성, 수정, 삭제 이력을 시간순으로 표시
- **상대 시간 표시**: "방금 전", "3분 전", "2시간 전" 등 직관적 시간 표시
- **Diff 뷰어**: 이전 버전과 현재 버전의 변경 내용 비교

### 1.9 결과 / 실행계획 / 콘솔

쿼리 실행 결과를 확인하고, 실행 로그를 실시간으로 모니터링할 수 있는 공간입니다.

| 탭 | 설명 |
|-----|------|
| **결과** | 그리드 형식으로 데이터를 표 형태로 표시, CSV 내보내기 지원 |
| **실행계획** | 쿼리의 예상 실행 계획을 트리 형태로 시각화 |
| **콘솔** | 실행 로그, 에러, 경고 메시지 실시간 확인 |

## 2. 쿼리 변경 이력 (`/query-history`)

모든 쿼리의 변경 이력을 한 곳에서 조회할 수 있는 페이지입니다.

**주요 기능:**
- 좌측 쿼리 목록에서 쿼리 선택
- 삭제된 쿼리 필터링 (체크박스)
- 쿼리별 변경 횟수, 마지막 변경 시간 표시
- 변경 이력 선택 시 상세 Diff 비교 가능

---

## 3. 릴리스 버전관리 (`/release-version`)

쿼리를 릴리스 버전 단위로 그룹화하여 관리하는 페이지입니다.

**주요 기능:**
- 새 버전 생성
- 버전별 포함된 쿼리 목록 확인
- 버전 검색

---

## 4. DDL 생성기 (`/ddl-generator`)

데이터베이스 스키마를 관리하기 위한 DDL(Data Definition Language) 생성 도구입니다.

**3가지 작업 모드:**

| 모드 | 설명 |
|------|------|
| **스키마 변경** | 기존 테이블의 컬럼 추가/수정/삭제 DDL 생성 |
| **새 테이블 생성** | 새로운 테이블 생성 DDL 작성 |
| **자주 하는 작업** | 자주 사용하는 DDL 템플릿 |

**사용 방법:**
1. 좌측 카탈로그 트리에서 대상 테이블 선택
2. 변경 사항 추가
3. DDL 생성 버튼 클릭

## 사용 워크플로우

### 새 쿼리 작성 및 저장

```
1. 도메인 선택 (APS / DP / CUSTOM)
       ↓
2. 카탈로그에서 테이블 구조 확인
       ↓
3. SQL 에디터에서 쿼리 작성
   (필수: WHERE project_id = @project_id)
       ↓
4. 매개변수 설정
   - "SQL에서 @매개변수 자동 감지" 클릭
   - project_id에 프로젝트 선택
   - 추가 매개변수 값 설정
       ↓
5. 쿼리 실행 (Ctrl+Enter) 및 결과 확인
       ↓
6. 메타데이터 입력
   - 쿼리 ID (고유 식별자)
   - 쿼리 이름
   - 쿼리 타입 (Read/Write)
   - 릴리스 버전 지정
       ↓
7. [저장] 클릭
```

### 저장된 쿼리 불러오기

```
1. 좌측 "저장된 쿼리" 패널에서 쿼리 클릭
       ↓
2. 에디터에 새 탭으로 쿼리 로드
       ↓
3. 매개변수 값 설정 (project_id 등)
       ↓
4. 실행 또는 수정 후 저장
```

### 외부 서비스에서 쿼리 호출

저장된 쿼리는 **쿼리 ID**를 통해 외부 서비스에서 호출할 수 있습니다. 이를 통해 프론트엔드 애플리케이션이나 다른 백엔드 서비스에서 미리 정의된 쿼리를 실행하고 데이터를 페칭할 수 있습니다.

## 주의사항

1. **project_id 필수**: 모든 쿼리에 `WHERE project_id = @project_id` 조건이 필수입니다. 누락 시 "WHERE 절에 project_id 조건은 필수로 작성해야 합니다" 경고가 표시되며, 실행 시 "파라미터에서 project_id 값을 찾을 수 없습니다" 에러가 발생합니다.

2. **테이블 참조 형식**: 반드시 `catalog.schema.table_name` 3단 형식으로 작성해야 합니다.
   - 올바른 예: `postgresql.mzc_aps.cfg_item_master`
   - 잘못된 예: `cfg_item_master` (카탈로그/스키마 누락)

3. **쿼리 ID 변경 불가**: 한번 저장된 쿼리의 ID는 수정할 수 없습니다. ID는 외부 서비스 연동의 키값이므로 신중하게 설정하세요.

4. **카탈로그 용도 구분**:
   - `iceberg`: APS 실행 결과/리포트 데이터 (out_*, rpt_* 등)
   - `postgresql`: 설정/마스터 데이터 (cfg_*, at_* 등)
