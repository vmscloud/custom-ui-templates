# 📘 **작업 지시서: 라이트 테마 기반 다크 모드 컬러 생성 매뉴얼**

본 문서는 Light Theme 색상세트를 기반으로, 동일한 톤과 역할 구조를 유지하는 Dark Theme 색상셋을 생성하기 위한 작업 절차를 정의한다.  
다른 LLM에게 전달하여 동일한 품질의 다크모드 팔레트를 일관되게 생성하기 위한 목적의 문서이다.

---

# 1\. 🎯 **목표**

- Light Theme에서 사용되는 모든 색상 변수를 기반으로, \*\*역할(role)·명도(level)·의도(intention)\*\*를 유지하면서 Dark Theme용 신규 색상 팔레트를 설계한다.
- 단순 반전이 아닌, **서비스 UI와 자연스럽게 어울리는 블루그레이 기반 다크 톤**을 구성한다.
- 결과물은 **CSS 변수 형태** 또는 **SCSS map 형태**로 제공한다.

---

# 2\. 🎨 **다크모드 설계 원칙**

## 2.1 배경 계열 (background)

- 완전한 블랙은 사용하지 않고, **#0f131a ~ #232e3f** 사이의 블루그레이 계열을 사용한다.
- light의 밝기 단계(back, backdark1~3 등)을 유지하되, 대응되는 dark 톤을 계층적으로 배치한다.

## 2.2 보더(border)

- 원본보다 **명도 40~60% 낮춘** 블루그레이 계열로 변경.
- UI 경계가 흐려지지 않을 정도로 대비 확보.

## 2.3 텍스트(font 계열)

- font1을 가장 밝고 선명한 텍스트(#e5e9f2 ~ #fff)로.
- font7로 갈수록 점점 더 어두운 블루그레이(#5b6270)로.
- 기존 라이트 테마의 상대적 레벨 구조를 그대로 유지할 것.

## 2.4 강조/accent 계열

- 원본의 민트·하늘색 계열은 다크모드에서 **저채도 청록·청록블랙 계열**로 치환.

## 2.5 status/error/info/success/warning

- 원본 색상 톤을 유지하되, 어두운 배경에서 더 선명하게 보이도록 **보정된 명도 + 채도 미세 조정**.

## 2.6 아이콘(icon 계열)

- 텍스트 계열보다 약간 낮은 대비를 가지는 **밝은 블루그레이 기반**으로 설정.
- disabled는 그보다 명도 20~30% 다운.

## 2.7 shadow

- 기존 라이트보다 농도를 강화 (#00000055 등)하여 깊이감을 유지.

---

# 3\. 📐 **변환 규칙**

아래는 라이트 테마의 변수명/역할을 기반으로 다크모드 변수값을 재설계하는 규칙이다:

| 라이트 역할                | 다크모드 치환 규칙                             |
| -------------------------- | ---------------------------------------------- |
| background/light           | 블루그레이 기반 Dark 배경군으로 단계 매칭      |
| border                     | 대비 유지하며 darker tone 적용                 |
| font1                      | 최상위 대비 → 거의 white                       |
| fontN                      | n이 증가할수록 명도·채도 ↓                     |
| icon                       | 텍스트 대비 살짝 낮은 색상                     |
| accent                     | 라이트 색상 hue 유지, 명도 ↓ 채도 ↓            |
| error/info/success/warning | hue 유지, dark 배경 대비에 맞게 채도/명도 조정 |
| disabled                   | 명도 크게 낮추고 채도 축소                     |

---

# 4\. 🧩 **출력 형식**

LLM은 반드시 아래 중 하나로 출력해야 한다:

### ✔ CSS 변수 (권장)

```css
--color-example: #123456;
--color-example-2: #abcdef;
```

### ✔ 또는 SCSS map

```scss
$colors-dark: (
  --color-example: #123456,
  --color-example-2: #abcdef,
);
```

---

# 5\. 📝 **입력되는 라이트 테마 색상 목록 처리 규칙**

1.  제공된 라이트 테마의 변수명, 구조 그대로 사용한다.
2.  누락된 변수는 추가 생성하지 않는다.
3.  입력된 light 색상값의 의미를 판단해 dark용 대응 값을 만든다.
4.  동일한 역할을 가진 색상 그룹들은 톤/명도 체계를 유지한다.

---

# 6\. 🧪 **예시 입력 (Light)**

```css
--color-back: #ffffff --color-error: #dc5a5a --color-font1: #233253...;
```

---

# 7\. 🧪 **예시 출력 (Dark)**

(다른 LLM이 생성해야 하는 결과 예시)

```css
--color-back: #0f131a;
--color-error: #e17f7f;
--color-font1: #e5e9f2;
...
```

---

# 8\. ✔ LLM 응답 요약 기준

- 색상은 모두 **실제 UI에 사용 가능한 값**이어야 한다.
- 색상 계열의 **연속성**을 보장한다.
- 원본 라이트 테마의 역할 구조를 **최대한 보존**한다.
- 단 한 줄의 설명 없이 “색상값만 제공하는 모드”도 지원 가능해야 한다.
- 하지만 기본적으로는 “전체 변환 결과”를 출력한다.

---

# 9\. 📦 LLM이 반드시 지켜야 할 요구사항

1.  **원본 라이트 테마의 감성·톤을 유지할 것**
2.  **반전·자동변환 등의 단순 알고리즘 적용 금지**
3.  **디자인 감각 기반의 수동적 톤 매칭을 수행할 것**
4.  **다크모드 전체 팔레트가 자연스럽고 실제 적용 가능한 품질이어야 함**
5.  **변수명은 절대 변경하지 말 것**
6.  **결과는 마크다운 코드블록으로 출력할 것**
